# agent-history のマスキング対象の定義

`apps/agent-history` で対話履歴を表示するときに伏せる情報の定義。実装（`internal/redact`）はこの文書に従う。

- 作成日: 2026-11-05
- 根拠の集計: 手元の Claude Code（150 セッション）と Codex（48 セッション）の全履歴。表示対象の文字列（タイトル、作業ディレクトリ、本文、ツールの入力と結果）44,952 個に下書きのルールをかけて件数を数えた。値そのものは見ずに、件数とキー名だけを集計した

## 目的と前提

- **目的**: 画面共有、スクリーンショット、録画で履歴を見せても、認証情報・個人情報・自分の環境を特定できる情報が映らないようにする。
- **表示だけを変える**。`~/.claude` や `~/.codex` のファイルは読むだけで、書き換えない。
- **既定でオン**。サイドバーのチェックボックス（`Mask`）で切り替え、起動時の状態は `-mask=false` で変えられる。
- **できる範囲での対応（ベストエフォート）**。パターンで検出するので、漏れも誤検出もある。漏れると困る用途（公開する資料など）では、最後に目で確認すること。迷う場合は伏せる側に倒す。ただし、本文が読めなくなるほどの誤検出は避ける。

## 置き換えの表記

`‹…›`（山括弧に似た記号 U+2039 / U+203A）で囲む。Markdown の記法と衝突せず、伏せた場所だと一目で分かるようにするため。

| 表記 | 意味 |
|---|---|
| `‹redacted:<種類>›` | 認証情報（種類は下表） |
| `‹email›` | メールアドレス |
| `‹ip›` | IP アドレス |
| `~` | 自分のホームディレクトリ |
| `‹user›` | ユーザー名・氏名・指定した語 |
| `‹host›` | マシンのホスト名 |

## 対象

### A. 認証情報（secrets）

常に伏せる。種類が分かるものは種類を残す（何が漏れかけたのかを後で把握できるように）。

| 種類 | 検出 | 実データ |
|---|---|---|
| `private-key` | `-----BEGIN … PRIVATE KEY-----` から `-----END … PRIVATE KEY-----` まで（END が無ければ末尾まで） | 0 |
| `anthropic-key` | `sk-ant-` + 20 文字以上 | 0 |
| `openai-key` | `sk-`（`proj-` / `svcacct-` / `admin-` を含む）+ 20 文字以上 | 0 |
| `github-token` | `ghp_` `gho_` `ghu_` `ghs_` `ghr_` + 30 文字以上、`github_pat_` + 22 文字以上 | 0 |
| `slack-token` | `xoxb-` `xoxp-` など + 10 文字以上 | 0 |
| `aws-key` | `AKIA` / `ASIA` + 英大文字・数字 16 文字 | 0 |
| `google-key` | `AIza` + 35 文字 | 0 |
| `jwt` | `eyJ…` の 3 区切り（各 8 文字以上） | 12 |
| `token` | `Bearer` / `Basic` の後の 16 文字以上 | 8 |
| `credentials` | URL の `scheme://user:password@` の `user:password` 部分 | 17 |
| `value` | 秘密らしい名前のキーへの代入の値（下記） | 下記 |

**秘密らしいキーへの代入（`value`）**: `password=…`、`"api_key": "…"`、`export GITHUB_TOKEN=…` など。

- キー名: 末尾が `password` / `passwd` / `secret` / `token` / `api_key`（`apikey` `api-key`）/ `access_key` / `private_key` / `credential`（複数形も含む）。前に何が付いてもよい（`AI_ANALYST_READ_TOKEN`、`clientSecret` など）。大文字と小文字は区別しない。
- 値: 次を**除外**する。下書きでは 1846 件検出したが、大半が誤検出だった。
  - 数値だけのもの: `max_output_tokens: 128000`（これだけで 1548 件）、`maxTokens=4096`
  - 変数・式の参照: `$TOKEN`、`${token}`、`process.env.…`、`os.environ[…]`、`secrets.…`（GitHub Actions）
  - 短すぎるもの（8 文字未満）と、すでに伏せてあるもの（`‹` で始まる）
  - 値が `true` / `false` / `null` / `none` / `undefined`
- キー名が `…tokens` で終わるもの（`max_tokens`、`output_tokens` などトークン数）は対象外。
- URL の認証情報も、パスワード部分が `$…` / `${…}` なら伏せない（テンプレートであって秘密ではない）。

### B. 個人情報（PII）

| 対象 | 検出 | 置き換え | 除外 | 実データ |
|---|---|---|---|---|
| メールアドレス | `local@domain.tld` | `‹email›` | ローカル部が `git`（`git@github.com:` などの SSH URL）。ドメインが `example.com` / `example.org` / `example.net` / `example.co.jp` か、TLD が `.example` / `.test` / `.invalid` / `.localhost`。`noreply@anthropic.com`（コミットの Co-Authored-By） | 計 695（うち `anthropic.com` 423、`example.*` 25、それ以外 156 を伏せる対象と見込む） |
| IPv4 アドレス | 0〜255 の 4 組 | `‹ip›` | `127.*`、`0.0.0.0`、`255.*`（マスク） | 330（ループバック 127、プライベート 113、その他 90） |

- `…@users.noreply.github.com` は GitHub のユーザー名を含むので**伏せる**。
- プライベート IP（10/8、172.16/12、192.168/16）も、社内ネットワークの構成が分かるので伏せる。
- 電話番号、住所、クレジットカード番号などは誤検出のほうが多くなりそうなので、今回は対象外（下の「対象外」を参照）。

### C. 環境を特定できる情報

実行中のユーザーとマシンから自動で集める。

| 対象 | 取り方 | 置き換え | 実データ |
|---|---|---|---|
| 自分のホームディレクトリ | `os.UserHomeDir()` | `~`（`~/ghq/…` のようになる） | 8390 |
| 他のユーザーのホーム | `/Users/<名前>`、`/home/<名前>`、`C:\Users\<名前>` | `/Users/‹user›` など | 157 |
| OS のユーザー名 | `user.Current().Username`、ホームのディレクトリ名 | `‹user›` | 10351（ホーム以外の場所での出現も含む。例: `ls -l` の所有者欄） |
| 氏名 | `user.Current().Name` と、それを空白で区切った各部分 | `‹user›` | 45 / 8 |
| ホスト名 | `os.Hostname()`（`.local` を除いたもの、最初の `.` より前） | `‹host›` | 4 |

- 語として一致するものだけを置き換える。英数字の語は前後が英数字でないことを条件にし、日本語の語などはそのまま一致させる。大文字と小文字は区別しない。長い語から順に置き換える。
- **URL エンコードされたパス**（`%2FUsers%2Falice%2F…`）も対象にする。ホームは `~` にし、`%2F` の直後の語も区切られたものとして扱う（`F` が英字なので、単語境界だけを見ると一致しない）。実データの確認で、この形の漏れが 1 件見つかった。
- **2 文字以下の語は無視する**。誤検出が多すぎるため。

### D. 利用者が指定する語

`-mask-words a,b,c` で指定した語を `‹user›` にする。自動では決められないもの向け。

- GitHub のユーザー名（パスの `github.com/<名前>/` に出てくる）
- 会社名・組織名・顧客名・社内のドメインやサービス名
- 同僚の名前

GitHub のユーザー名や組織名は公開リポジトリのパスにも出てくるので、既定では伏せない（伏せるとパスが読みにくくなる）。

## 適用範囲

| 場所 | マスク |
|---|---|
| サイドバー: セッションのタイトル、プロジェクトのパス | する |
| リストの行の名前（スクリーンリーダーの読み上げ、タイプして選ぶ機能で使う `ListState.Label`） | する（画面に出なくてもアクセシビリティの情報から読めるため。UI のテストで見つかった） |
| 読み込みエラーの文言 | する（ファイルパスを含むため） |
| ヘッダー: タイトル、作業ディレクトリ、ブランチ | する |
| 会話: 入力、返答、thinking、ツールの入力と結果、補足、要約 | する |
| 「Copied: …」の表示 | する |
| 「Copy resume command」/「Copy session ID」でクリップボードに入れる値 | **しない**（実際に使うコマンドなので、伏せると動かない） |
| セッション ID | しない（ランダムな ID で、個人を特定しない） |
| 検索 | 元の文字列で検索する（伏せた語でも見つけられる） |

- 本文のマスクは量が多いので、会話を読み込む goroutine の中でかける。オンとオフを切り替えたときは会話を読み直す。
- サイドバーとヘッダーの文字列は少ないので、表示するときにかけて結果をキャッシュする。

## 実装と確認の結果（2026-11-05）

- 実装: `apps/agent-history/internal/redact`。テスト: `redact_test.go`（上の各行の伏せる例と除外の例）と、UI のテスト `TestMasking`。
- 実データ（198 セッション）の全エントリにかけて、伏せたあとにホームディレクトリとユーザー名が残っていないことを確認した（0 件）。値は出力していない。
- トークンの接頭辞（`sk-ant-` `ghp_` など）が残った 2 件は、grep のパターン（`'sk-ant-|ghp_|…'`）として書かれた文字列で、秘密ではなかった。
- 処理時間: 全セッション合計 2.3 秒、最も重いセッションで 0.16 秒（別の goroutine で実行するので画面は固まらない）。各ルールに「小文字にした文字列がこれを含まなければ正規表現を実行しない」手がかりを付けて、6.9 秒から短縮した。

## 対象外（今回はやらない）

- **会話の内容に含まれる業務データ**（顧客名、DB の行、ログの中身など）: 一般的なパターンでは検出できない。必要なら `-mask-words` で語を指定する。
- 電話番号、住所、クレジットカード番号、マイナンバー: 誤検出が多い割に、手元の履歴にはほぼ出てこない。必要になったら足す。
- アカウントや組織の UUID: 表示対象のレコード（Claude Code の `session-owner` など）は読んでいないので、画面には出ない。
- 一時ディレクトリのランダムな名前（`/private/var/folders/…`、`/tmp/claude-501/…`）: 個人を特定しない。
- 画像（貼り付けたスクリーンショット）: 表示していない（`[image]` と出すだけ）。
- 秘密の値を一般的な文字列（エントロピーの高い文字列など）として検出すること: Git のハッシュや UUID の誤検出が多いのでやらない。

## テストの方針

- `internal/redact` の単体テストで、上の各行を「伏せる例」と「伏せない例（除外）」の両方で確かめる。
- テストに使う秘密情報は形式だけを合わせたダミーにする（実在のキーを入れない）。
- 実データへの適用は、コミットしない一時テストで件数を見て確かめる（値は出力しない）。
